# Zephyr Ada — Ada Interrupt Handling

## Goal

Implement `Interrupt_Priority` mutual exclusion and `Attach_Handler` support for Ada
protected objects on Zephyr. This is the natural follow-on to the `ada_tasking` branch.

Branch to create: `ada_interrupts` (from `ada_tasking`)

## Background

Ada protected objects with `Interrupt_Priority` must use interrupt masking (not task
priority raising) for mutual exclusion. On Zephyr, the primitive is `irq_lock()` /
`irq_unlock()`. This is distinct from the ceiling locking protocol already implemented
for software priorities.

Currently:
- `Lock`/`Unlock` always call `Set_Priority` (k_thread_set_priority) — wrong for ISR context
- `Attach_Handler` raises `Program_Error`
- `Current_Interrupt` always returns `No_Interrupt`
- No `irq_lock()`/`irq_unlock()` anywhere in the RTS

Ada type definitions (system.ads):
- `Priority           : 0 .. 30`  — task priorities, ceiling locking via k_thread_set_priority
- `Interrupt_Priority : 31 .. 31` — interrupt priorities, mutual exclusion via irq_lock()

## Architecture

### Lock/Unlock strategy (s-taprob.adb)

```
Lock:
  if Object.Ceiling >= System.Interrupt_Priority'First then
    Object.Interrupt_Key := STPO.Interrupt_Lock   -- irq_lock()
  else
    STPO.Set_Priority (Self_Id, Object.Ceiling)   -- k_thread_set_priority (existing)
  end if;

Unlock:
  if Object.Ceiling >= System.Interrupt_Priority'First then
    STPO.Interrupt_Unlock (Object.Interrupt_Key)  -- irq_unlock()
  else
    STPO.Set_Priority (Self_Id, Object.Caller_Priority)
  end if;
```

The `Protection` record gains an `Interrupt_Key` field (unsigned, Zephyr irq_lock key).

### Attach_Handler flow (elaboration time)

For each protected object with `Attach_Handler => Ada.Interrupts.Names.FOO_IRQ`:

1. GNARL calls `OS_Interface.Attach_Handler (Handler_Wrapper'Access, IRQ_ID, PO_Prio)`
2. `Attach_Handler` calls C shim: `irq_connect_dynamic (irq, priority, wrapper, arg, 0)`
3. C shim calls `irq_enable (irq)`
4. At IRQ time: Zephyr calls `wrapper(arg)` from ISR context
5. Wrapper acquires the PO lock (irq_lock path), calls the Ada procedure, releases lock

### ISR wrapper

The ISR wrapper is a thin C trampoline:

```c
void ada_irq_wrapper(const void *arg) {
    Ada_ISR_Handler handler = (Ada_ISR_Handler)arg;
    handler();  /* calls the Ada protected procedure directly */
}
```

The Ada protected procedure's Lock (irq_lock) is a no-op re-check when called from ISR
context, since interrupts are already masked at the current level on ARM Cortex-M.

### Ada.Interrupts.Names

Generated by `dt_to_ada.py` from interrupt nodes in the DTS. One constant per IRQ:

```ada
package Ada.Interrupts.Names is
   UART0_IRQ : constant Interrupt_ID := 12;
   TIMER0_IRQ : constant Interrupt_ID := 17;
   ...
end Ada.Interrupts.Names;
```

## Implementation Steps

### Phase 1 — irq_lock mutual exclusion (no Attach_Handler yet)

This makes `Interrupt_Priority` protected objects safe even without ISR handlers —
useful for protecting data shared between tasks and a bare C ISR.

- [ ] **Step 1**: Add C shims for `irq_lock`/`irq_unlock` to `ada_zephyr_shims.c`
  - `unsigned int ada_irq_lock(void)` → `irq_lock()`
  - `void ada_irq_unlock(unsigned int key)` → `irq_unlock(key)`

- [ ] **Step 2**: Add `Interrupt_Lock`/`Interrupt_Unlock` to `System.OS_Interface`
  - `s-osinte.ads`: declare `type Interrupt_Lock_Key is mod 2**32;`
  - `s-osinte.ads`: `function Interrupt_Lock return Interrupt_Lock_Key`
  - `s-osinte.ads`: `procedure Interrupt_Unlock (Key : Interrupt_Lock_Key)`
  - `s-osinte.adb`: implement via `ada_irq_lock`/`ada_irq_unlock` imports

- [ ] **Step 3**: Add `Interrupt_Lock`/`Interrupt_Unlock` to `System.Task_Primitives.Operations`
  - `s-taprop.ads`: delegate declarations

- [ ] **Step 4**: Update `Protection` record in `s-taprob.ads`
  - Add `Interrupt_Key : System.OS_Interface.Interrupt_Lock_Key`

- [ ] **Step 5**: Update `Lock`/`Unlock` in `s-taprob.adb`

## Constraints and Notes

- **Single-core only**: No SMP considerations needed (matches rest of RTS).
- **Ravenscar restriction**: Static `Attach_Handler` only at elaboration; dynamic
  `Ada.Interrupts.Attach_Handler` is allowed under Jorvik but not pure Ravenscar.
  Implement static first; dynamic can be optional.
- **`Interrupt_Priority` range**: Currently `31 .. 31` (one level). This is correct for
  Jorvik profile. Expanding to multiple IRQ priority levels (matching ARM NVIC bits)
  is a possible future extension but not needed for correctness.
- **ISR context detection**: `k_is_in_isr()` is available in all Zephyr versions.
  The existing `Is_Task_Context` stub in `s-taprop.adb` already plans for this.
- **No `Owner` check in ISR**: The ceiling violation check (`if Object.Owner = Self_Id`)
  must be skipped when called from ISR context (no ATCB, `Self` would return null).
- **ARM NVIC priority inversion**: The Ada `Interrupt_Priority` (single level 31) maps
  to a specific NVIC priority. Use Zephyr's `CONFIG_*_IRQ_PRIORITY` conventions.
  The `dt_to_ada.py` generator should read the `interrupt-priority` DTS cell.
